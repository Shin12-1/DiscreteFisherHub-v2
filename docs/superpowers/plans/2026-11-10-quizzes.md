# Quizzes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Quizzes placeholder with accessible, untimed Logic practice quizzes, explanations, missed-question review, and saved attempts.

**Architecture:** Add an authored static question bank for the three available Logic lessons, with pure helpers for validating, scoring, and selecting a mixed review. Persist the latest 20 attempts in local storage for guests and the existing Supabase table for signed-in learners. Wire the quiz list, question flow, results, history, and unavailable-topic states into the current shared page renderer.

**Tech Stack:** Vanilla HTML/CSS/JavaScript ES modules, JSON, browser local storage, existing Supabase client, Node.js built-in assertions.

**Spec:** `docs/superpowers/specs/2026-11-10-quizzes-design.md`

## Global Constraints

- Offer one short quiz per available Logic lesson and a mixed Logic review.
- Give immediate, accessible feedback with an explanation for every answer.
- Show a score, let learners review missed questions, and allow another attempt.
- Save attempt history locally for guests and to Supabase for signed-in learners.
- Keep quizzes untimed, ungraded, and separate from XP and lesson completion.
- Leave topics without lesson/question content unavailable; do not imply their quizzes exist.
- Do not add a leaderboard, exam mode, or new framework/dependencies.
- Preserve the shared app shell, theme support, mobile layout, and keyboard focus behavior; include Quizzes in the five-item mobile quick navigation in place of the empty Practice entry.
- Preserve existing unrelated worktree changes in `js/core/auth.js`.

## Review Focus

- A missing, duplicate, malformed, or lesson-mismatched question bank must fail validation; cover with validator tests.
- A mixed review must not mutate the source bank or duplicate questions, including when fewer questions than requested exist; cover with deterministic selection tests.
- Missing answers and zero-correct attempts must produce valid scores and all applicable missed questions; cover with scoring tests.
- Guest history and signed-in history must use the correct store and expose storage errors; cover with local and mocked Supabase tests.
- Keyboard-only and narrow-screen use must retain clear progress, answer feedback, and usable controls; cover with a manual browser smoke checklist.
